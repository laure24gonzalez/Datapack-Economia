# Sistema de Recompensas por Mobs

## Objetivo

Todos los mobs deben conservar el **100% de su loot vanilla**, sus probabilidades, comportamiento con Looting y cualquier condición especial de Minecraft.

El sistema de EconomíaRPG **NO reemplaza** los drops originales.

Únicamente añade un **pool adicional** con las monedas correspondientes.

Las monedas deben ser completamente independientes del loot vanilla.

---

## Reglas

- Conservar todos los drops originales de Minecraft.
- Conservar todas las probabilidades vanilla.
- Conservar todas las mecánicas de Looting.
- Conservar equipo, rarezas y condiciones especiales.
- Añadir únicamente un pool extra con la moneda correspondiente.
- Nunca eliminar ni modificar el comportamiento original del mob.

# Billetera / Wallet

## Cómo funciona

La wallet de EconomiaRPG usa un saldo virtual por jugador. Ese saldo se guarda en un scoreboard y se muestra en la sidebar del juego.

Las monedas físicas sirven como una representación externa del dinero:
- Bronce = 1 punto de valor
- Plata = 10 puntos de valor
- Oro = 100 puntos de valor

Cuando un jugador deposita monedas físicas, esas monedas se convierten en saldo virtual. Cuando retira dinero, el saldo virtual se convierte de nuevo en monedas físicas que aparecen en su inventario.

Este diseño permite que el sistema sea simple, limpio y fácil de expandir con comerciantes, tiendas, pagos entre jugadores y futuras mecánicas económicas.

## Entrada de comandos compatible con datapack vanilla

Un datapack vanilla no puede registrar un comando personalizado como /billetera. Por eso, la entrada debe hacerse con una de estas opciones soportadas por Minecraft:

1. /function economiarpg:ver
2. /function economiarpg:guardar
3. /function economiarpg:sacar
4. /function economiarpg:pagar
5. /trigger economiarpg.wallet_cmd set 1/2/3/4

### Recomendación

La opción más simple y compatible es usar /function para las acciones principales. Si querés una experiencia más cómoda, la siguiente mejora natural sería un libro interactivo o un menú con botones, pero sin crear un comando falso.

## Estilo corto y fácil de recordar

El flujo pensado para el jugador es muy simple:

- /function economiarpg:ver
- /function economiarpg:guardar
- /function economiarpg:sacar
- /function economiarpg:pagar

Si luego quisieras un comando tipo /billetera guardar, eso se haría desde un plugin o un servidor con comandos personalizados, no desde un datapack puro.
